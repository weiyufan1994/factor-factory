# Ultimate 经验闭环维护与 PF/VV 验收

目标不是多保存文件，而是让下一位研究员找到并正确使用此前的经济、数学和实验经验。研究入口仍然是 Ultimate；先理解研报或用户假说，再参考知识库。本文不改变正在进行的 PF/VV 试验。

## 已接通的维护链

| 研究状态 | 保存什么 | 下一轮如何读到 |
|---|---|---|
| Step6 执行及校验完成，包括 reject | 原生知识记录的显式经验字段 | 工作区索引、项目经验导出、共享关键词索引，以及已配置的语义索引 |
| 已执行的本地 IS 研究失败或暂停 | 独立 episode：发生了什么、停在哪里 | 自动保存、共享导出和关键词回读；不把报错当成经济解释 |
| 有实质研究报告，但原生 Step6 未完成 | 研究员据原文整理的 research_note | 可检索的辅助经验，明确保留未完成状态和证据限制 |
| 旧经验被纠正或撤回 | 保留原始记录，使用显式修订关系或撤回状态 | 活跃索引排除撤回内容；不删除历史文件 |

程序自动处理记录、导出、索引和维护状态。经济解释与可迁移经验仍由研究员根据证据撰写，不从收益数字或程序异常自动编造。Ultimate Skill 已要求研究员在终局或真正中断时检查维护结果，并通过实际消费者回读，不需要用户另行提醒。

维护失败不得改变研究结论，也不得自动重跑因子。当前自动接入覆盖正常完成、通用命令失败和主代理 Step6 暂停路线；进程强杀和所有历史专用提前退出并不保证立即触发钩子。恢复时执行下面的维护命令补齐。

## 不重跑研究的修复入口

在项目根目录执行：

```bash
python3 scripts/maintain_factorforge_knowledge.py \
  --workspace-root /absolute/path/to/existing-factor-workspace \
  --report-id EXISTING_REPORT_ID
```

只接受该工作区已有的本地 IS Ultimate 报告。完成的 Step6 走原生经验导出；未完成的执行走独立 episode。它不执行因子、回测、收益诊断或 OOS，不改原报告。检查返回的 `default_readback`、导出结果和语义维护状态；最近一次独立维护结果位于 `knowledge/maintenance/latest.json`。`REFRESHED` 不是经济假说获得支持。

## 本地语义检索

现有关键词检索和机制图谱继续保留，新增 BGE-M3 向量召回并按排名融合。程序异常类 episode 不进入经济经验向量库。检索只考虑当前调用显式可见的记录；源文本变化而缓存未刷新时，语义路线显示过期并退回关键词，不返回旧向量命中。

本机已用已有完整 BGE-M3 缓存实际构建并查询。模型在独立 Python 环境中运行，CPU 最多两线程、批次为二，不启动常驻服务、不自动下载模型。可分发源码含 `requirements-knowledge.txt`；本机模型、环境、绝对路径配置和向量缓存不进入发布包。

其他安装的一次性配置位于 `knowledge/retrieval/semantic_config.json`，字段示例：

```json
{
  "enabled": true,
  "model_id": "BAAI/bge-m3",
  "model_path": "/absolute/path/to/complete/local/bge-m3",
  "python_path": "/absolute/path/to/isolated/python",
  "index_path": "factorforge_semantic_index.json",
  "threads": 2,
  "max_length": 512
}
```

显式重建：

```bash
python3 scripts/build_factorforge_semantic_index.py --root /absolute/path/to/project
```

未配置或模型不可用时仍可使用关键词与图谱；检索结果会显示语义路线是否使用及退回原因。`FACTORFORGE_DISABLE_EMBEDDING_RETRIEVAL=1` 可禁用语义查询。相似度只表示文本接近，不是机制成立、因子有效或因果关系已识别。

## 每条有用经验应回答的问题

- 原本的经济假说、要估计的数学对象是什么？
- 算子或实现保留了什么信息、丢掉了什么信息？有哪些前提？
- 哪些状态只是候选解释，哪些状态已经有可检验的识别方式？
- 某种处理在哪些数据、时间尺度、市场条件下观察到什么结果？是否有反例？
- 结果是数学性质、样本观察，还是仍待检验的经济/心理机制？
- 原文、公式、实现和实验来源在哪里；下一项能区分竞争解释的检验是什么？

适用条件、regime 识别与处理效果分开保存。未知可以保留；一次分组回测不能自动证明状态识别或因果效果。Factor Forge 知识库借鉴 IOG 的有条件关系和证据关联，但两个系统的数据和索引不合并。

## PF/VV 本轮结束后的验收

1. 作者 baseline 与独立扩展始终明确分开，原始经济逻辑、算法和必要重建假设可追溯。
2. Step2/3 展示至少一项真实的知识调用：检索到了什么、为何适用或不适用、如何影响建模或检验。不是只附一串命中文档。
3. Step4/5 实现并检验所声明的对象，比较保持一致；表现差时区分实现、测量、交易表达和机制解释，不能证明的原因仍标为未知。
4. Step6 对支持、拒绝或未定结论都整理可迁移经验，并自动维护共享索引；未完成 Step6 的研究不得被补录伪装成完成。
5. 另一个不带本次对话历史的研究上下文，仅从库里召回经验，说明适用边界，提出一个有经济与数学依据的下一步；同时能发现反例或选择不采用。

全部通过，才能说这条具体研究闭环达到了测试目标。并不要求 PF/VV 扩展一定赚钱，也不能由一个案例证明知识库已经完备、所有算子关系均被验证，或 RAG 普遍提高了研究质量。

本轮维护已补录 Signed-A 原报告中的经验，明确它不是 PF/VV 作者 baseline，也没有宣称原生 Step6 已完成。实际新进程检索已召回该经验及条件算子、瞬态信号方法等记录；下一位研究员是否正确采用，留待上述第 5 项验收。

2026-09-13 验证：离线回归 529 项通过，3 项需要显式真实执行引擎的集成测试未运行，2 项历史 Git 状态相关测试按原套件配置排除。独立代理对维护增量复核通过。实际维护回读为 true，语义缓存包含 18 条可检索记录、1024 维；这些数量只证明当前维护和召回路线工作，不证明内容完整或经济结论正确。
