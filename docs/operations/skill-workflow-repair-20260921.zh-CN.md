## 研究员现在怎样继续

1. Ultimate 执行到 Step3B，生成实际代码和拟测试内容。
2. Step2 研究员阅读源文/spec、代码及实际 helpers；Step3 修复，Step2 复审。
3. Step3 对已审版本执行确定性或 parity 测试，记录真实结果。
4. 从 Ultimate Step4 继续原任务。内部拆段不缩小用户要求的完整研究范围，不需要用户再批准常规审查。
5. Step4 发现疑似 bug 时通知 Step2/3，停止受影响工作；区分实现、规格、数据和真实实证问题。修复、复审、回归后，只重算受影响结果，保留旧结果及其失效原因。

缺少审查沿用现有失败返回，不是可自动续跑的 PAUSED 调度器。wrapper 不会代写审查、执行日志中的任意命令或自动给其他 agent 发消息。实际协调仍由 Ultimate 研究员通过任务渠道完成。

紧凑记录位于研究工作区既有 journal；字段说明见 [local-code-review.md](../../skills/factor-forge-ultimate/references/local-code-review.md)。版本校验只防止旧审查套用新代码，不是身份、签名或新 Host 平台。不能仅靠记录证明审查质量、helper 完整性或测试确实执行。
