# Skill 阅读与路由核对（2026-10-10，本地候选）

比较基线是 R35p8 提交 `3f1e916b61ec5b1d8f3b73d89209c782b6e928ce`，候选是当前清理分支。
`packaging/research-skills.json` 列明默认 11、可选 2 和兼容转发 3 个 Skill，并逐场景列出前后阅读路径。
这是分发输入与测量计划；尚未改变用户已安装的 Skill 或正在运行的研究。

## 测量口径

同一研报、普通 local IS、简单日度 direct-code 因子、既有数据权限；没有 Qlib 或 OOS 操作。
使用 UTF-8 原始字节而非估算 token。阶段内按路径去重；累计按场景顺序去重。
可选托管资料不算普通任务，但源文输入、代码、行情也不算“指导文件”，独立记录。
表格是明确路由的静态读量，不声称独立研究员已经照此完整走通。

完整主文的注册集合由原包 16 个、172,085 bytes 变为候选默认 11 个、46,215 bytes；前后 frontmatter 共 4,883 / 2,237 bytes。可选/兼容内容仍存在于源码，默认集合变化不等于全部文件消失。
累计必读量下降约 35.5%，不能用主文下降约 73% 代替它。当前最大的必读来源仍包括研究协议字段（17,564 bytes）、代码评审流程（13,078 bytes）和实质 Council（18,445 bytes）；它们只在对应动作加载。

本轮将旧版本/异常工件恢复说明移到 `code-review-recovery.md`，普通代码评审指南减少 5,066 bytes。正常评审、测试和恢复 Step4 的规则不变；具体中断或记录失败时才加载该恢复文件。新链接及计数回归 7 项通过。此文件未纳入普通顺畅研究的静态必读集合；实际试用若打开它，仍须如实计入真实读量。

## 复算与实际试用

```sh
python3 scripts/measure_skill_reading.py --output /tmp/factorforge-skill-reading.json
```

结果逐场景给出 `required_paths`、`stage_required_bytes`、`cumulative_unique_bytes`、重复读量和五个最大文件。
独立试用前 `actual_files_opened=null`。后续可用 `--opened-guidance-log <actual.json>` 输入真实打开记录：场景 ID 对应 `guidance_files`、`source_code_data_files` 和说明实际证据的 `evidence_note`。工具单独计算真实指导文件数和重复打开次数；作者填的计划不是独立使用记录。
