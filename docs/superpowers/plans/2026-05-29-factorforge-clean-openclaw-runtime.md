# Factor Forge Clean OpenClaw Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the OpenClaw-on-EC2 Factor Forge operating path so Humphrey is only a message-triggered caller, while Factor Forge CLI owns run identity, artifact roots, SSM execution, validation, and proof reporting.

**Architecture:** Keep Step1-6 as independent step skills, but introduce a single control-plane CLI and immutable active-run registry. OpenClaw/Humphrey never scans artifacts, never selects roots, never interprets SSM history, and never falls back to old runs; it calls one command and returns the proof ledger generated by code.

**Tech Stack:** Python 3 standard library, existing Factor Forge scripts, AWS CLI/SSM, existing `factor_factory.runtime_context`, existing `scripts/factorforge_run_registry.py`.

- Mac baseline repo: `/Users/humphrey/projects/factor-factory`, branch `main`, HEAD `af203a9e9f4000c73c62eb4a3785fa3a73b2510b`, clean worktree at plan creation.

  `/var/lib/factorforge/artifacts/<report_id>/<run_id>`.

- Every status report must be generated by code and include `report_id`, `run_id`, `artifact_root`, `repo_sha`, `ssm_command_id`, `worker_instance_id`, `created_at_utc`, `status`, and `block_token`.

## Target Architecture

```text
Feishu / Humphrey
  -> OpenClaw skill command
  -> factorforgectl
      -> active_run_registry.json
      -> Step1 local/OpenClaw PDF tool route
      -> Step2 local LLM route
      -> Step3A local data-contract route
      -> Step3B/Step4 worker SSM route
      -> Step5 worker SSM route
      -> Step6 local/OpenClaw LLM route
      -> proof_ledger.json
  -> Humphrey returns proof_ledger summary only
```

## File Responsibilities

- Create `scripts/factorforgectl.py`
  - Single operator CLI for `init-run`, `run-step1`, `run-step2`, `run-step3a`, `run-worker-step3b4`, `run-worker-step5`, `run-step6`, `proof`, and `status`.
  - Rejects any report with no active registry entry.
  - Rejects any attempt to read old roots unless the registry points to them.

- Create `factor_factory/run_control.py`
  - Pure Python library for run identity, active registry loading/writing, artifact root validation, and proof ledger writes.
  - No AWS calls.

- Create `factor_factory/ssm_control.py`
  - Thin AWS CLI wrapper for SSM `send-command` and `get-command-invocation`.
  - Requires explicit `instance_id`, `repo_sha`, and `artifact_root`.
  - Captures stdout/stderr into proof ledger.

- Create `docs/operations/factorforge-openclaw-runtime-v2.zh-CN.md`
  - Operator SOP for Humphrey/OpenClaw.
  - Defines what Humphrey may and may not do.

- Modify `docs/operations/factorforge-entrypoint-registry.json`
  - Add `scripts/factorforgectl.py` as the only production operator entrypoint for OpenClaw/Humphrey.

- Modify `scripts/run_factorforge_entrypoint_hygiene_smoke.py`
  - Add checks that OpenClaw/Humphrey entrypoints route through `factorforgectl.py`.
  - Add checks that production status/proof commands do not scan `/tmp` or S3 fallback snapshots.

## Acceptance Criteria

- Legacy production directories are archived, not deleted.
- EC2 v2 repo path is clean and pinned to a known commit.
- Humphrey/OpenClaw has only one allowed Factor Forge operator entrypoint: `scripts/factorforgectl.py`.
- `factorforgectl status/proof` never scans `/tmp`, workspace top-level artifact roots, or S3 fallback snapshots.
- Missing active run returns `BLOCK_ACTIVE_RUN_NOT_FOUND`.
- Root mismatch returns `BLOCK_ACTIVE_RUN_IDENTITY_MISMATCH`.
- Worker stopped returns a status fact, not a run failure, unless live file read is explicitly requested.
- Every successful run writes a proof ledger under the active artifact root.
