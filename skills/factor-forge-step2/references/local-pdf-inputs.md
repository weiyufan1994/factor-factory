# Local PDF input and landing

Read for `--local-is-only` PDF intake, not for a source-free hypothesis or later code review.

## Local PDF extraction input

For `Ultimate --local-is-only` PDF research, use actual agent-authored primary
and challenger raw specs. The Step1 alpha idea must explicitly reference them
under `local_agent_spec_inputs.primary/challenger` (workspace-relative path,
raw SHA-256, role, report/factor/route identity), together with the chief's
`chief_canonical_core`: `raw_formula_text`, `operators`, `required_inputs`,
and `rebalance_frequency`. Both routes independently check the adjudicated
core; their descriptions and original source disagreements remain preserved.
Unresolved core disagreement stops before a master is generated. A historical mechanical
consistency score is not a chief decision or semantic proof.

Missing local PDF specs must not invoke the old generic price-volume-correlation
template. Local `direct_code` additionally requires the actual code contract
and the Step1-authored measurement program on the alpha idea. No template may
invent a formula, economic hypothesis, model, neutralization, or success claim
to make the pipeline proceed. Existing explicit hosted adapters and non-PDF
routes retain their own inputs. Continue only through the Ultimate wrapper.

## Automatic PDF Resolution

The runner must resolve the original PDF in this order:
1. `factorforge/data/report_ingestion/report_registry.json`
2. `factorforge/objects/handoff/handoff__{report_id}.json`
3. any usable path fields inside `alpha_idea_master`

If no local PDF path can be found, the run must fail explicitly instead of pretending completion.
